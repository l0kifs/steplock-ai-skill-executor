## Skill Discovery & Loading

### Registry Files
Two YAML registry files are used, merged together:

| Registry | Path | Auto-created | Purpose |
|----------|------|--------------|---------|
| User-wide | `~/.steplock/skills-registry.yaml` | Yes | Skills available in every project |
| Project-local | `./.steplock/skills-registry.yaml` | No | Project-specific skills |

### Registry Format (`skills-registry.yaml`)
```yaml
skills:
  - /path/to/skill1
  - /path/to/skill2
```

### Skill Loading Flow
1. `create_server()` in `entry_points/mcp/server.py` creates a `CompositeSkillRegistry`
2. `CompositeSkillRegistry` wraps both user and project registries (if project registry exists)
3. `SkillExecutionService.list_skills()` calls `ISkillRegistry.list_skill_paths()` to get all paths
4. For each path, `YamlSkillLoader.load()` parses the `SKILL.yaml` file
5. Skill name and description are extracted and returned to the MCP client

### SKILL.yaml Format
```yaml
name: my-skill
description: When and why to use this skill.
steps:
  - id: step-1
    instruction: steps/step1.md  # file path or inline string
    verify: scripts/verify_step1.py  # optional verification script
    on_fail: retry  # retry | abort (default: abort)
    helpers:  # optional helper scripts
      - scripts/get_context.py
```

### Key Classes and Functions
- `SkillsRegistry` (`infrastructure/skill/registry.py`): Reads paths from a YAML registry file
- `CompositeSkillRegistry` (`infrastructure/skill/registry.py`): Merges multiple registries
- `YamlSkillLoader` (`infrastructure/skill/loaders.py`): Parses SKILL.yaml into `Skill`/`Step` models
- `SkillExecutionService.list_skills()` (`application/skill/services.py`): Iterates all registry paths and loads skills
- `SkillExecutionService.start_skill()` (`application/skill/services.py`): Finds skill by name, creates session

## Data Flow
```
MCP stdio request
  → FastMCP tool decorator (entry_points/mcp/server.py)
    → SkillExecutionService (application/skill/services.py)
      → ISkillRegistry.list_skill_paths() (infrastructure/skill/registry.py)
      → ISkillLoader.load() (infrastructure/skill/loaders.py)
      → ISessionRepository.save/find() (infrastructure/skill/repositories.py)
      → IVerificationRunner.run() (infrastructure/skill/runners.py)
```

## Key Abstractions
- `ISkillRegistry` (`application/skill/ports.py`): Port for skill path discovery from YAML registry
- `ISkillLoader` (`application/skill/ports.py`): Port for loading skill definitions from paths
- `IVerificationRunner` (`application/skill/ports.py`): Port for running verification scripts
- `IHelperRunner` (`application/skill/ports.py`): Port for running helper scripts
- `ISessionRepository` (`application/skill/ports.py`): Port for session persistence
- `SkillExecutionService` (`application/skill/services.py`): Main orchestrator for skill execution workflows
- `SkillsRegistry` (`infrastructure/skill/registry.py`): Filesystem-backed registry reading from YAML — auto-creates `~/.steplock/` on first access
- `CompositeSkillRegistry` (`infrastructure/skill/registry.py`): Merges multiple registries into one (user + project)
- `YamlSkillLoader` (`infrastructure/skill/loaders.py`): Parses SKILL.yaml into domain Skill/Step models — resolves relative paths to absolute
- `create_server()` (`entry_points/mcp/server.py`): Factory for FastMCP server dependency injection

## Invariants
- Domain layer (`domains/skill/`) must not import from application, infrastructure, or entry_points

## Agent Notes
- **Skill Discovery**: Skills are discovered from two merged registry locations:
  - `~/.steplock/skills-registry.yaml` (auto-created on first run)
  - `./.steplock/skills-registry.yaml` (project-local, optional)
- **Registry Format**: YAML file with `skills:` list containing absolute directory paths
- **Skill Definition**: Each skill directory must contain `SKILL.yaml` with name, description, and steps
- **Verification Scripts**: Exit code 0 = pass, non-zero = fail with guidance returned to agent
- **Helper Scripts**: Declared per-step in SKILL.yaml, run via `run_helper_script` tool
- **Session Persistence**: In-memory only (lost on server restart)
- **No Auth**: MCP server has no authentication or authorization
- **Filesystem Paths Hidden**: Registry paths are never exposed to the agent, only skill names
